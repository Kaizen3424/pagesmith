## 1. Product definition

A **framework-agnostic, zero-database, git-backed CMS package**: a headless TypeScript core SDK + a fully brandable React admin SPA. Content stays plain JSON files in the user's GitHub repo; the admin talks to `api.github.com` directly with a fine-grained PAT (browser-only; no server component in v1).

**Stage A (v1 "done") = replaces Sveltia on yve**: owner + non-technical founder edit 4 collections (products, collections, 5 page documents, site settings) end-to-end: browse → edit → autosave → Save = one squash commit to `main` → see per-entry build status ("Live ✓") without leaving the admin. Founder does not need to understand git.
**Stage B (v2+, OSS)**: hardening/publication — README/demo, Decap `config.yml` importer, OAuth Worker auth, GitLab backend, PR editorial workflow optional mode, WYSIWYG optional, i18n.

**Success criteria (testable):**
1. Cutover complete on yve with Sveltia preserved at `/admin-legacy` as instant rollback.
2. Founder completes, without owner help: edit product (price/text/image swap/add product via template), edit collection, edit a page document, edit site settings; publish shows "Live ✓" per entry.
3. Zero silent-failure paths: every failure state has a human-phrased surface + "copy message for [partner]".
4. Site build (zod gate) passes with schemas imported from the CMS config package; the 6 known incumbent drift cases are pinned by a CI fixture.
5. All security invariants (§8) and reliability invariants (§9) enforced by automated tests.

**Non-goals v1**: WYSIWYG markdown, i18n outside string-extraction readiness, roles/audit, branch/PR editorial workflow (staging-branch+PR assessed, deferred — user fork), visual/iframe editing, mobile-specific admin layout, GitLab.

## 4. Core architecture & contracts

### 4.1 GitBackend (transactional)
Methods (all take `branch: string` param — never hardcoded): `getRef(branch)`, `listChangedFiles(baseSha, headSha)` (set-diff of two recursive trees, keyed `{path → {sha, mode, type}}`; base==head→∅; renames = delete+add, fine), and **`commitChanges({adds, updates, deletes}, baseHeadSha)`** as THE write primitive (blobs→`createTree` with `base_tree`→`createCommit`→FF-only `updateRef force:false`; git-data API never one-put). Optional capability object, exhaustive compile-time literal: `capabilities: { commitStatus: boolean, branches: boolean, … }` (+ `commitStatuses?(sha)` on GithubBackend only). `writeFile` = sugared single-file commit for settings docs. Media service lives ABOVE backend; `listMedia/uploadMedia/deleteMedia` are path-mapped via config, not transport.
Guards: assert `!truncated` on every recursive tree read; `truncated:true` → degrade to per-subtree non-recursive walks; contents-`dir` listing capped at 1000 → not used for correctness decisions; >1MB reads via `/git/blobs` (base64 ≤100MB); per-commit entry cap (~500) enforced client-side; **client-side SHA-1 precompute** to skip `createBlob` when content unchanged (fewer calls, faster retries).

### 4.2 Two registries (the custom-widget fix)
- `core/fields`: `defineFieldType(name, {parse, serialize, validate, defaultE, meta})` — pure, no React, no IO. Declaration-merging registry macro so `{Value, Raw, Config}` types flow to the renderer without a second schema.
- `admin/widgets`: `defineWidget(fieldTypeName, Component)` joined **by name**. Custom contract = `WidgetProps{ value, onChange, error, fieldConfig, useField(), services{ entryIndex(coll), readEntry(ref), siblingValues() } }` — **never `backend`/token access in WidgetProps (standing veto)**. Cross-entry display resolution (relation shows "Iris No. 7") is owned by admin `ServicesProvider` built at the composition root; `services.entryIndex` is sync from Query cache w/ async fallback.

### 4.3 Cache + state law
TanStack Query = the ONLY UI cache; core's ETag cache lives inside `queryFn`s; keys carry `refSha`; a ref-watcher ( POLL + focus refetch, `visibilitychange`-gated, If-None-Match) bumps one sha atom → cascade invalidation. Snapshot store is monotonic (advances only after a ref-verified commit). `rebase({formValue, dirtyPaths, oldBase, newBaseRaw, oldRaw}) → {mergedRaw, conflicts}` is pure (dirty decided in value domain via `fieldEquals`, merge in raw domain; unknowns from new raw only; no-op iff byte-equal) + property tests (11 listed in ADR-0004).

### 4.4 Save state machine (exhaustive, one transition table, not scattered booleans)
`editing(baseSha) → dirty → queued → committing → published | conflict(needs field-freeze) | failed(retryable→backoff cap→paused(manual)) | paused(reason{network,auth,quota})`.
- One outstanding `updateRef` per repo from ALL sources (media+entry); always fresh `getRef()` immediamente before each commit (queued second save does NOT false-conflict after first commit moves main).
- `published` = honored by **content, not receipt**: on `updateRef 200` → immediately published (idempotent re-verify later); on network-died-after-server-applied → re-verify via tree sha equality; orphan blobs after failed commit = documented harmless (git GC'd, never "cleaned up" by us).
- Drafts: written to IndexedDB **before first network call** (test-asserted); deleted only after the ref is **observed** to contain the commit shas.
- `paused` resume is never a blind re-dispatch: one batch rebaseline (`getRef` + `listChangedFiles`) lands in `queued|conflict`. BroadcastChannel save-lock = **lease (token + heartbeat + TTL, silent steal + full rebaseline)** with `storage`-event fallback (Safari <15.4); payloads never carry sensitive content; UX-serialization only (CAS remains the only correctness mechanism).
- Crash/boot recovery: run invariant engine over surviving drafts — tuple-equal+canon-equal→discard draft; tuple-equal+canon-differs→offer resume; drained→conflict UI. tx progression is callback-driven (never timer-cadence); `visibilitychange` wake → verify-then-rebuild before trusting queued state.

## 5. Save pipeline (the algorithm + conflict predicates)

1. Validate (strict): all dirty fields via core validators = zod from config (stricter than incumbent YAML allowed); **can't commit anything unclean**.
2. **Cross-entry sweep, verdict classes** (UX veto honored) — at commit time refetch all ~16 content files fresh (2KB each, cheap; offline ⇒ coverage-phrased honest copy):
   - (a) her entry invalid → inline field errors, no commit.
   - (b) unrelated entry invalid → **commit her file anyway**, advisory chip: "Your change is committed, but the site's update is paused by an older problem: {entry} points at a removed product ('{title}'). Your product goes live as soon as that's fixed." + CTAs: "Take me there" (repair-chip on the invalid relation row) + "Copy message for [partner]".
3. `getRef()` fresh → build changed set (paths + bytes) → client SHA-1 precompute → create blobs (≤5 concurrent, Retry-After honored) → createTree (base_tree) → createCommit → updateRef FF-only → invariants below.
4. **Conflict predicate** (fresh-binding BLOCKER fix): remote side = fresh recursive tree of freshly fetched head INSIDE the transaction (never the ETag cache). Apply iff ∀ changed path p: `remoteTuple == baseTuple` OR `canon(remoteBytes) == canon(baseBytes)` (auto-rebase silently, adopt remote bytes as new base; mode-only diff → auto-restore w/ warning entry in commit body; type change → block). Created paths additionally require absence (create-collision = conflict unless canon-equal). Binaries: byte/sha-only + visual before/after choice.
5. Same-file overlap → **field-granularity freeze** (never whole-entry Take/Show): classify → non-overlapping fields auto-merged w/ announcements ("Kept [Milan]'s caption · Kept your description"); overlap → per-field decision rows ("saved by [Milan], 3:05 PM" vs "yours", one click each); any discarded version archived as tombstone draft 30 days; attribution from commit author, fallback display name from config, NEVER "someone".
6. Deploy status: poll **check-runs** endpoint `GET /commits/{sha}/check-runs` (Cloudflare Workers Builds emits check runs; combined statuses empty — would read "unknown" forever). Per entry keyed to `latestCommitSha`, strips: ⏳ Building (newest save) / ✓ Live now: {formatted money} — your newest save {X} still building / ✓ Live {X}. No check run within grace (120s, 5s→10s cadence, jittered) → "Building status unavailable" **never "failed"** + deep links. Later head advance → "superseded by {sha}" annotation; global banner "live site reflects current head". Commit messages: generated `chore(cms): …` + user-editable; **`[skip ci]`-class tokens rejected**; never force:true; cross-repo nothing.
7. Probe (session start + re-probe on any 401/403/422 from a write + soft TTL 60min for protection/archived; never cached persistently; never inside a quota-blocked window): `GET /rate_limit` (token-valid + quota) → `GET /repos/{o}/{r}` (visibility, archived, default_branch cross-check, viewer permissions) → `GET /branches/{branch}/protection` **only if admin permission** (404=unprotected; non-admin = "unknown, runtime classifier decides") → `GET /commits/{head}/check-runs?per_page=1` (Checks read validation; 403 → status pipeline off + guided "re-mint w/ Checks read").
8. Failure taxonomy = **typed `GitError` union** owned by backend: `AuthExpired(401) | Scope(403 content) | NotFound(404 repo-not-in-token) | Conflict(422 FF) | ProtectedBranch | Archived | RateLimit{resetAt} (primary header-driven) | Secondary{retryAfter} | Network | Unknown` — classifier matches body strings only where status collides ("Resource not accessible by personal access token", "Repository was archived so is read-only", /secondary rate limit|abuse/, "Bad credentials"); every screen switches on the type; founder surfaces never show GitHub prose.
9. Rate-limit park: Save click during throttle → parked in one-flight queue, pill "waiting on GitHub — resumes in {s}", button disabled-not-error, editor fully editable, drafts persist, resume event-driven (not setTimeout-only).

## 8. Security & token model (invariants, enforceable)

1. Template output (`{{title}} · € {{price}}` etc.) = **text-node-only mustache-lite** (regex substitution → React text child). No handlebars, no `dangerouslySetInnerHTML`, ever. Golden XSS fixtures (summary, preview_path, alt, view-group patterns, `<img src=x onerror>`). Biome `noDangerouslySetInnerHTML` + grep-gates in CI (also no `eval`, `new Function`, `innerHTML=`, `Object.assign`/deep-merge on parsed-untrusted JSON, stray `fetch(` outside github-client module).
2. `safePath()`/`safeUrl()` on EVERY read AND write: repo paths relative to declared media root; reject `..`, backslashes, `%2f/%5c` decodings, absolute/service prefixes, drive letters; URLs = http/https/relative allowlist; render via `<a target=_blank rel="noopener noreferrer">`. `preview_path` interop runs safeUrl too.
3. SVG: uploads **rejected v1** (ADR); existing repo SVGs render via `<img src=blob:>` only (no svg-inline/object/iframe). Uploads raster-only via canvas re-encode (EXIF stripped by construction, orientation preserved, ~400KB target); decode pre-caps (≤15MB file, naturalWidth/Height pre-check); GitHub-side caps = backstop.
4. `parseUntrustedJson()` = the only entry/config parse (re-keyed prototype-free: strips `__proto__|constructor|prototype`; golden pollution fixtures `{"__proto__":…}` + nested `constructor.prototype`); post-parse caps: entry ≤2MB, depth ≤64, list items ≤5k; render recursion guard; YAML config (v2 importer) requires js-yaml alias-max assertion fixture; numeric keys string-prefixed (`entry:${n}`) everywhere.
5. Token: never in URL; access only through one github-client module; state = `AuthProvider` interface; lifecycle: probe on login, re-probe on 401/403/422-after-write; wipe on sign-out/failed-bootstrap/401; multi-tab = persisted branch makes BroadcastChannel lease load-bearing (ADR note); DevTools visibility = documented non-boundary. `/admin` loads ZERO third-party runtime scripts (fonts/icons self-hosted; Sveltia CDN gone from that path) — enforced by e2e catch-all route assertion (allowlist: `self`, `api.github.com`, `blob:`, `data:`; anything else aborts).
6. CSP/response headers shipped as committed artifact + smoke-tested:```

X-Frame-Options: DENY · X-Content-Type-Options: nosniff · Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=() · X-Robots-Tag: noindex
``` (style-src inline = Radix positioning; style-only, never script). Site also ships `<meta robots noindex>` on /admin and `Disallow: /admin` + `/admin-legacy` in robots.txt; no site nav link.
7. Supply chain: pnpm 10 `onlyBuiltDependencies` committed w/ per-entry reason comments (`esbuild`, `lightningcss`, `@tailwindcss/oxide` — NOT playwright/shiki; SWC only if chosen); frozen-lockfile CI; `pnpm audit --json` + versioned `security/audit-waivers.yml` (advisory, package+range, context, owner, **expiry ≤90d auto-fail**, upstream link); Renovate `minimumReleaseAge` + manual review for Radix/octokit majors (consolidation/rename churn); CI e2e prod-purity byte-scan: no `.map`, no `sourceMappingURL`, no `mockServiceWorker.js`, no telemetry-endpoint strings.
